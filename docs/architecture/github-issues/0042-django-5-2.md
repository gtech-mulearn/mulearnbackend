## Why

Django 4.2's support ended in April 2026. Django 5.2 LTS is the next supported step and it still supports Python 3.10 ([ADR-050](../adr/ADR-050-platform-versions.md)).

## Before you start

- Issues 0012, 0040 and 0041 must be merged.
- Read the Django 5.0, 5.1 and 5.2 release notes, especially the removals: pytz support, `USE_TZ` defaults, `LogoutView` GET, the `iterator()` chunk size and the PBKDF2 iteration counts.

## What to do

1. Upgrade `Django` to the latest 5.2.x in `requirements.txt` and the lock file. Upgrade compatible pins for `django-cors-headers`, `django-storages`, `drf-spectacular` and the other Django add-ons.
2. Set `USE_TZ` explicitly to its current value, so the new default doesn't change behaviour.
3. Fix the deprecation warnings counted by the `legacy` job that are removals in 5.x.
4. Run the characterization tests, both test tiers and the legacy ratchet.
5. Leave a two-week staging soak before production. A maintainer records the soak result on the issue.

## Acceptance criteria

- [ ] The characterization tests pass unchanged.
- [ ] Both tiers pass, and the legacy ratchet shows no new failures.
- [ ] `python manage.py check --deploy` is no worse than before.
- [ ] The staging soak shows no new error types.

## How to test

```sh
scripts/test.sh tests/characterization/ tests/
```

## Out of scope

- Python upgrades.
- Django 6.x.

## Notes for reviewers

This changes the framework under everything. Two reviewers; ship it alone in its train.
